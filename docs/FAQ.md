# 常见问题（FAQ）

> 维护时机：出现新的高频问题，或脚本行为变化导致既有答案失效时，更新本文档。
> 本文档可通过油猴脚本菜单中的「常见问题」入口随时打开。

### Q: 点击按钮没有反应？

A: 请确保已正确安装 Tampermonkey 扩展，并且脚本已启用。可以在浏览器右上角的 Tampermonkey 图标查看。

### Q: 下载的图片不清晰？

A: 本脚本会自动将图片URL中的尺寸标识替换为原图：
- 微博：将 mw690、bmiddle、orj360 等替换为 large
- X：将 name=small、name=large 替换为 name=orig

### Q: 下载失败怎么办？

A: 
- 检查网络连接
- 尝试刷新页面后重新下载
- 如果是部分图片失败，可能是微博图片加载问题

### Q: 为什么按钮/toast 显示「已发起」而不是「已下载」？

A: v1.5.10 起，微博图片及视频直链、X 图片字节、X GIF 转换产物、微博 Live Photo 合并产物均优先通过 `GM_download`（`saveAs: false`）保存。该通道能够通过回调确认下载结果，成功时显示「完成」。

如果 `GM_download` 不可用或失败（例如脚本管理器未授权下载权限），脚本会回退到浏览器原生 `a[download]` 通道。此时脚本无法确认文件是否已经落盘，因此显示「已发起」；如果浏览器开启了「下载前询问每个文件的保存位置」，回退时还可能弹出保存对话框。

显示「已发起」时，请检查浏览器下载列表；如果频繁出现，可检查 Tampermonkey 下载权限、下载管理器接管设置，参考下方有关保存位置弹窗的排查说明。

### Q: X 的 GIF 转换失败怎么办？

A: 「X平台GIF自动转换」开启时，转换在浏览器本地完成：解码 MP4 并逐帧编码为 GIF，较长或较高分辨率的动图转换更慢、占用更多内存，个别情况下可能失败。失败的文件会计入下载失败数量（toast 只显示成功/失败数量，不单独提示）。可在油猴菜单关闭「X平台GIF自动转换」后重新下载，直接保存 `.mp4` 源文件；也可关闭部分标签页释放内存后重试。

### Q: 文件名是怎么生成的？

A: 默认命名格式为 `{platform}_{postId}_{index}`，即：

- 微博：`weibo_{帖子ID}_{序号}.jpg`
- 微博 GIF：`weibo_{帖子ID}_{序号}.gif`
- 微博 live photo（默认合并）：`weibo_{帖子ID}_{序号}.MP.jpg`（单文件 Motion Photo）
- 微博 live photo（关闭合并）：`weibo_{帖子ID}_{序号}.jpg` + `weibo_{帖子ID}_{序号}.mov`（同名配对，注入 Apple Live Photo 元数据）
- 微博视频：`weibo_{帖子ID}_{序号}.mp4`
- X 图片：`x_{帖子ID}_{序号}.jpg`
- X GIF：`x_{帖子ID}_{序号}.gif`（关闭自动转换时为 `.mp4`）
- X 视频：`x_{帖子ID}_{序号}.mp4`

可以在油猴菜单点击 **“文件命名设置”** 自定义命名模板（微博与 X 各一份）。可用占位符：

| 占位符 | 含义 | 缺失时 |
| --- | --- | --- |
| `{platform}` | 平台（weibo / x） | — |
| `{postId}` | 帖子 ID | — |
| `{index}` | 帖内序号（从 1 开始） | — |
| `{author}` | 作者（X 为 @handle，微博为昵称） | 压缩掉空占位段与多余分隔符 |
| `{source}` | 源站原文件名（多为 hash 型） | 同上 |

面板中点击或拖动占位符标签即可插入输入框并实时预览；扩展名由脚本按媒体类型自动添加，不参与模板；文件名非法字符自动替换为 `_`，模板清空或保存“恢复默认”即回到默认命名。

微博作者取帖头昵称，支持信息流、个人主页、详情、搜索和移动端页面；正文中的 @提及不作为作者。X 的 `{author}` 使用不带 `@` 的账号 handle，优先取帖内昵称节点的 @handle，其次取帖内个人主页链接；页面改版导致两者缺失时，详情页/媒体预览页会回退从页面地址的 `/handle/status/帖子ID` 首段提取。作者识别失败时模板中的 `{author}` 段会被省略（产物与默认模板形态一致），并在下载完成后提示「未能识别作者」，便于区分「模板没生效」与「作者缺失」。X 图片先获取原图字节，再按同一套模板规则保存，避免直链被下载链路改成 `HV86CnuboAAZCcn.jpg` 这样的 CDN 原文件名；默认模板仍应生成 `x_帖子ID_序号.jpg`。

### Q: 下载的文件名变成一串 UUID（如 `73502e18-....exif`）怎么办？

A: 这是本机下载链路的问题，不是文件损坏：脚本传入了正确文件名，但个别下载管理器（如 IDM）或脚本管理器“下载 BETA”模式在处理 `GM_download` 的 Blob 下载时忽略了它，用内部 UUID 加内容嗅探的扩展名落盘。X 图片、GIF 转换与 Live Photo 合并产物优先经 `GM_download` 静默保存并保留模板名，正常环境（Tampermonkey + 浏览器 API 下载模式）不会出现此问题；若你的环境出现 UUID 文件名，请：在 IDM 的“选项 → 下载”中关闭对该浏览器的接管（或排除 `blob:` 链接）；在 Tampermonkey「设置 → 下载 BETA」将「下载模式」选为「浏览器 API」。如果直链图片也出现 UUID 文件名，多为 Tampermonkey 下载 API 权限未授予导致下载降级，在 Tampermonkey 的下载权限授权提示中点允许即可恢复正确命名。

### Q: 为什么每次下载都弹出保存位置对话框？如何恢复静默下载？

A: 微博图片与视频直链、X 图片字节（含 GIF 转换与 Live Photo 合并产物）均优先经 `GM_download`（显式 `saveAs: false`）静默保存，该通道在用户开启“每次询问”设置时依然不弹窗。如果遇到弹窗，按场景排查：

- **Tampermonkey 未授权下载 API 权限**时，`GM_download` 不可用，下载会降级到浏览器原生 `a[download]` 通道——该通道严格遵循“每次询问”设置，开启时会逐文件弹窗，网页脚本无法绕过；在 Tampermonkey 弹出的“允许 Tampermonkey 开始下载”授权条中点一次允许即可恢复静默下载；
- **装了 IDM（Internet Download Manager）、Aria2 Explorer 等下载接管类工具**时，它们会拦截脚本与脚本管理器发起的下载，弹出各自的保存对话框或把下载转为 0 字节中断，该行为不受脚本控制——请在这类工具中关闭浏览器接管，或将 x.com / weibo.com 排除；
- **`GM_download` 偶发失败回退**到 `a[download]` 时同样遵循“每次询问”设置会弹窗，按上面两项恢复 `GM_download` 通道后即可静默；
- 若下载表现为 **0 字节中断或长时间无响应**：在 Tampermonkey「设置 → 下载 BETA」将「下载模式」选为「浏览器 API」，并允许下载权限；仍失败请更新 Tampermonkey 至最新版（部分 5.5.x 版本在该场景存在兼容问题）；
- 若仍逐文件弹窗，检查浏览器“下载前询问每个文件的保存位置”设置（`chrome://settings/downloads`），该设置影响浏览器的一切下载（包括其他网站与扩展），关闭即可恢复静默。

### Q: 为什么 X 的多图帖只下载了第一张？

A: 这是 Chrome 对网页“自动下载多个文件”的安全限制：同一页面连续发起多个下载时，Chrome 会在地址栏附近弹出“xxx.com 想要下载多个文件”的询问，未授权前后续下载会被拦下。点击一次“允许”即可，Chrome 会记住该站点（可在 `chrome://settings/content/automaticDownloads` 中查看或撤销），之后多图、GIF、视频等批量下载都会静默完成。微博站点同理，首次批量下载被拦时同样允许一次即可。

### Q: 下载的微博 Live Photo 是什么文件？为什么打开不动态？

A: 默认开启“微博LivePhoto自动合并”时，Live Photo 会被合并为单文件 Motion Photo（`.MP.jpg`，内嵌原视频，按 OPPO 真机格式逐字节对齐）。Windows 11 照片（2023+）、Google 相册、OPPO/一加（ColorOS 16 真机实测）、小米 HyperOS 相册、飞牛相册（fnOS，实测）等支持的查看器会显示动态效果；Mac 预览、iOS 相册因 Apple 采用成对文件机制，不识别任何单文件动态照片，只显示静态封面（这是平台限制）；三星相册因依赖私有 SEFT 尾部、与 OPPO 布局互斥，暂不支持。如果主要在 Apple 设备上看动态效果，可在油猴菜单关闭“微博LivePhoto自动合并”，脚本会保存**同名**的 `.jpg` 与 `.mov` 并注入 Apple Live Photo 配对元数据——把两个文件**一起**导入 iPhone/macOS 照片 App（AirDrop 整个文件夹、USB 或导入工具），即可作为 Live Photo 播放；只传其中一个文件或重命名任一侧都会破坏配对。合并失败时脚本会自动回退为这种配对保存方式。另外注意：微信/QQ/部分云盘传输会重压缩图片并剥掉动态照片元数据，请用 USB 或“原图”方式传输。
