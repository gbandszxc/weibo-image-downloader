### v1.5.6
- 修复：开启视频下载后，“只有部分账号可以回复”的 X 视频帖不显示下载按钮；兼容 `TweetWithVisibilityResults` 接口包装，正确解析视频及引用帖图片

### v1.5.5
- 修复：撤销 v1.5.4 的方向调整，直链图片/视频恢复 `GM_download`（显式 `saveAs: false`）优先——该参数显式为 false 时经 Tampermonkey 的浏览器下载 API 直连保存，即使用户开启「下载前询问每个文件的保存位置」也静默落盘且文件名正确，`onload` 确认后按钮恢复「完成」语义。v1.5.4 针对的弹窗经复测定位为两类：下载管理器（如 IDM、Aria2 Explorer）接管拦截，以及 `GM_download` 失败回退到浏览器原生通道（该通道严格遵循「每次询问」设置，属浏览器安全设计，网页侧无法绕过）
- 新增：`GM_download` 失败回退浏览器原生通道时，批量结束的 toast 追加「若弹出保存位置询问，请在 Tampermonkey 中允许下载权限」；`GM_download` 不可用（如 Violentmonkey）属正常降级，不提示
- 文档：FAQ 与 TECHNICAL 补充静默下载通道选择依据、下载接管工具（IDM/Aria2 等）排查项，以及 Tampermonkey「设置 → 下载 BETA → 下载模式」建议选「浏览器 API」的说明

### v1.5.4
- 修复：X（Twitter）直链下载经 `GM_download` 被脚本管理器直接转交浏览器下载器，Chrome 开启「下载前询问每个文件的保存位置」时逐文件弹出另存为对话框（微博因带 Referer 头走脚本管理器内部拉流路径不受影响）；直链图片/视频恢复脚本内拉流后走浏览器原生通道保存，保存过程静默、文件名稳定
- 修复：实测确认 `GM_download` 的完成回调在该直连路径下不可信（浏览器另存为挂起、文件被改名时仍报完成），按钮结束态相应调整：浏览器原生通道如实显示「已发起」，仅 `GM_download` 回退成功时显示「完成」
- 新增：FAQ 说明 Chrome「多文件自动下载」授权——各站点首次批量下载多个文件时需在地址栏提示中允许一次，授权后该站点永久静默

### v1.5.3
- 修复：微博时间线同页多个帖子下载时按钮状态互相联动（下载一条帖子，其他帖按钮跟着切换、且会被在途任务误拦截）；下载状态机改为按帖子隔离，帖子 ID 兜底不再共用同一毫秒时间戳
- 修复：直链图片/视频恢复 `GM_download` 优先下载，可确认下载结果时按钮结束态恢复「完成」语义；`GM_download` 不可用或失败时回退浏览器原生下载并如实显示「已发起」

### v1.5.2
- 新增：微博 LivePhoto 自动合并为单文件 Motion Photo（默认开启，可在脚本菜单关闭）：封面图与 `.mov` 视频在本地按字节合并为 `weibo_帖子ID_序号.MP.jpg`，不转码；Windows 11 照片、Google 相册、OPPO/一加（ColorOS 16 实测）、小米 HyperOS、飞牛相册（实测）等支持的查看器可直接播放动态效果。自动处理各平台识别兼容：OPPO 识别布局（MPF 双条目 + GainMap）、EXIF 厂商分支（去 Apple 化）、iPhone 原始多轨视频裁剪（修复识别正常但播放失败）
- 新增：关闭合并或合并失败回退时，保存**同名** `.jpg` + `.mov` 配对文件并注入 Apple Live Photo 配对元数据，两个文件一起导入 iPhone/Mac 照片 App 可作为 Live Photo 播放
- 修复：部分下载环境（下载管理器接管 Blob 下载）忽略脚本传入的文件名，导致文件落盘为 UUID 串加错误扩展名（如 `xxxx.exif`）；现统一改用浏览器原生下载通道，保留 `weibo_帖子ID_序号` 命名
